# Global Metrics Refresh — Implementation Plan

## Статус

- ✅ Завершено.

## Задача

- Один запрос истории вместо запросов по Dashboard и открытым сервисам.
- Полная история всех известных сервисов и метрик.
- Автообновление только при общем минутном пробеле.
- Ручное принудительное обновление в Settings.
- Минимальная нагрузка на слабые устройства и защита от повторных запросов.

## Исходное состояние

- WebSocket передавал все новые точки.
- Dashboard отдельно загружал историю выбранных метрик.
- Открытие сервиса отдельно загружало всю его историю.
- Ответы сливались и публиковались по одному запросу за раз.
- Ошибки истории не были видны пользователю.

## Реализовано

- Frontend хранит покрытие минутных bucket и список сервисов полного обновления рядом с IndexedDB-кэшем.
- Общий пробел ищется по объединению минутных bucket. Проверяется не более 1440 bucket за последние сутки.
- После первой проверки анализируется только новый диапазон.
- Старый кэш без метаданных и новый сервис вызывают обязательное полное обновление.
- Успешное обновление подтверждает диапазон. Одна общая остановка не создаёт повторные запросы для той же дыры.
- После ошибки действует пауза перед следующей автоматической попыткой. Ручная попытка доступна всегда.
- MegaBack принимает один список сервисов, параллельно читает текущий Flatline API и возвращает единый ответ.
- Выбор страницы, сервиса и гранулярности больше не запускает загрузку истории.
- Все гранулярности сохраняют прежние окна.
- HTTP middleware логирует число запросов, статус и длительность.

## Чеклист

- ✅ Единый history-контракт MegaBack.
- ✅ Backend-тесты глобальной загрузки.
- ✅ Метаданные покрытия и инкрементальный поиск общего пробела.
- ✅ Удаление загрузок по Dashboard и открытому сервису.
- ✅ Ручная кнопка обновления.
- ✅ Проверка Go и Angular.

## Результат

- Один глобальный refresh заменил загрузки, зависевшие от открытого экрана.
- Переходы между Dashboard и сервисами больше не определяют полноту истории.
- Передача сервисов и фиксированные окна сохранены как исходная версия контракта; оптимизация диапазонов вынесена в план 08.
- Надёжное восстановление после browser lifecycle, сетевых и серверных сбоев вынесено в отдельный план.
