# 44. Перегенерация картинок еды (парный план, фронт)

Основной план — бэк: `megaapp-back/plans/44-food-image-regeneration.implementation-plan.md` (маршрут перегенерации, события, версия каталога). Здесь только то, что делает фронт. Номер, имя и коммиты `[044]` общие для обоих репозиториев.

## Цель

В форме редактирования продукта видна текущая картинка, а у администратора есть кнопка «сгенерировать / перегенерировать». Состояние генерации и её провал видны пользователю. Продукты без картинки (сейчас «Желток» и «Салат Цезарь с креветками») чинятся этой кнопкой.

## Текущая архитектура

- Форма продукта одна на создание и правку. В режиме правки загружает свежие данные продукта и показывает поля, архивный флаг (для админа) и удаление. Картинки в форме нет.
- Картинка продукта определяется номером версии в записи каталога. Нет номера — нигде не рисуется ни картинка, ни заглушка, ни запрос.
- Адреса картинок строятся из номера версии: миниатюра в списке выбора, два варианта в дневнике и форме добавления записи.
- Событие «картинка готова» ставит номер версии в каталог и в текущие результаты поиска, но только если продукт уже есть в каталоге.
- Сигнала о провале нет. Картинка, которая не пришла, неотличима от картинки, которая ещё генерируется.
- Мутации каталога идут через очередь синхронизации. Она рассчитана на повтор при офлайне и идемпотентность по номеру операции.

## Решение

### Картинка в форме правки

Только в режиме правки, над полями: квадратное превью (миниатюра) и кнопка.

- Кнопка видна только администратору, по той же проверке, что уже решает показ архивного флага в этой форме. Превью видно всем. Сервер независимо отклоняет не-администратора, фронтовая проверка лишь убирает бесполезную кнопку.
- Нет картинки — пустое превью и кнопка «Сгенерировать».
- Есть картинка — превью и кнопка «Перегенерировать».
- Пока идёт генерация, кнопка заблокирована и показывает ход, превью остаётся прежним.
- Превью читает картинку из каталога, поэтому новая появляется сама, когда прилетает событие «картинка готова» (номер версии в адресе сбрасывает кеш браузера).
- Перегенерация при существующей картинке просит подтверждения: старая удаляется после успеха, и случайное нажатие не должно стоить хорошей картинки. Для генерации с нуля подтверждение не нужно.
- В режиме создания блока нет: продукта ещё нет, картинка запустится сама после сохранения.
- Кнопка не часть формы: не отправляет форму, не зависит от её валидности и не требует сохранения изменённых полей.

### Запрос на сервер

Обычный HTTP-вызов сервиса каталога, не через очередь синхронизации. Генерация платная и не должна копиться в офлайн-очереди и повторяться сама. Без сети кнопка просто сообщает об ошибке.

- Ответ «принято» включает состояние генерации. Ответ «уже в очереди» — то же самое.
- Ответы-ошибки превращаются в понятные уведомления: нет прав, очередь переполнена, генерация выключена на сервере, продукт не найден (после этого форма закрывается, как при удалении).

### Состояние «генерируется»

Живёт в сервисе каталога как набор номеров продуктов, а не в форме: переживает закрытие модалки и видно при повторном открытии.

- Включается при принятом запросе.
- Выключается событием «картинка готова» для этого продукта (с версией больше прежней) или событием «картинка не удалась».
- Запасной таймер сбрасывает состояние, если событие потеряно (обрыв сокета): после него пользователь может нажать снова. Длительность — с запасом над самой долгой серверной попыткой.
- Сброс при выходе из сессии, как у остального состояния сервиса.

### Событие «картинка не удалась»

Новый тип входящего сообщения сокета. Обработчик снимает состояние «генерируется» и показывает ошибку-уведомление с названием продукта. Событие приходит всем клиентам, но уведомление показывается только там, где генерацию запрашивали (состояние было включено), чтобы остальные устройства не получали шум.

### Событие «картинка готова» для неизвестного продукта

Если продукта ещё нет в каталоге локально, номер версии сейчас теряется. Достаточно, чтобы следующая догонка (версия каталога теперь растёт при готовой картинке, см. основной план) скачала каталог. Отдельной логики не нужно.

### Правила проекта

Стили кнопки и превью — готовые компоненты ui-kit и классы Tailwind, конфиги компонентов ui-kit в многострочном виде, новые сигналы и модальное подтверждение — по именованию из правил Angular проекта.

### Не меняется

- Отображение картинок вне формы. Заглушек для продуктов без картинки в списках нет: это отдельное решение о показе, не часть этого плана.
- Форма создания и порядок «сохранить, потом сервер сам ставит генерацию».
- Очередь синхронизации и её мутации.

## Идеи на будущее (сейчас не делаем)

## Проверка

- Типы без ошибок, линтер, тесты. Модульные тесты сервиса: включение состояния по принятому запросу, снятие по событию готовности и по событию провала, запасной таймер, сброс при выходе из сессии.
- Проверка в браузере после выкладки обоих репозиториев (изменения сигналов проверяются вживую, одних тестов мало): «Желток» → правка → «Сгенерировать» → превью обновляется без перезагрузки; перегенерация существующей картинки с подтверждением; провал показывает уведомление и возвращает кнопку.
