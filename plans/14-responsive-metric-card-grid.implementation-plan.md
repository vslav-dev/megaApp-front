# 14. Адаптивная сетка карточек метрик (auto-fit колонки, Компактный/Широкий режим)

## Статус

- ✅ Текущая реализация изучена (metric-card-grid, metrics-settings.service, metrics-dashboard).
- ✅ Судьба переключателя в шапке и логика 5-минутного схлопывания согласованы с пользователем (v2).
- ✅ Реализация выполнена, TypeScript и `ng build` чистые.

## Проблема

- Ширина карточки — жёсткое число px из настроек. При сужении окна карточки красиво переносятся, но в текущем ряду остаётся пустое место до момента, пока не наберётся ещё одна карточка на перенос.
- В настройках два параллельных режима (Small/Large: своя ширина + своя высота у каждого) + глобальный переключатель в шапке — избыточно дублирует размеры.
- Раскрытие карточки по клику включено/выключено по брейкпоинту экрана (`isDesktopScreen$$`, 768px), а не по факту — сколько колонок реально помещается в конкретном блоке.
- Решение "схлопывать график в 5-минутные бакеты или нет" завязано на сравнение настройки ширины с константой 600px — искусственный порог, не отражающий смысл того, что показывается.

## Решение — концепция

**Настройки размера.** Вместо пары Small/Large с раздельными шириной/высотой — одна целевая ширина + одна высота, общая для всех карточек в любом состоянии (обычная, раскрытая, в любом режиме).

**Режим отображения (переключатель в шапке — остаётся, меняется смысл).**
- *Компактный* — карточки стремятся к целевой ширине, число колонок N подбирается под фактическую ширину контейнера.
- *Широкий* — N принудительно = 1, каждая карточка занимает всю ширину контейнера, по одной в строке, вне зависимости от размера экрана.

**Подбор числа колонок (Компактный режим).** Для каждого инстанса сетки (сетка уже сама измеряет свою ширину через `ResizeObserver` — это остаётся) подбирается N, при котором фактическая ширина карточки в ряду (доступная ширина минус зазоры, делённая на N) ближе всего к целевой ширине. Эта ширина монотонно убывает с ростом N, поэтому решается простым перебором: увеличиваем N, пока переход к N+1 приближает фактическую ширину к цели; как только следующий шаг начинает удаляться — останавливаемся на предыдущем N. Точка переключения между N и N+1 автоматически оказывается ровно посередине между двумя фактическими ширинами — симметричный гистерезис без отдельного порогового параметра. Все обычные карточки в ряду получают одну и ту же вычисленную ширину — ряд всегда заполнен целиком, без пустого хвоста.

**Широкий режим.** Тот же формуле для ширины ряда, но N жёстко = 1 — поиск по N не выполняется, карточка получает всю измеренную ширину контейнера. Использует тот же `ResizeObserver`, что и Компактный режим — не отдельный код измерения, просто пропускается перебор N.

**Раскрытие по клику (Компактный режим).** Как и сейчас: клик по карточке → под её рядом появляется увеличенная копия во всю доступную ширину контейнера. Логика вставки (найти ряд кликнутой карточки, вставить копию сразу после него) не меняется — только источник числа "сколько карточек в ряду" становится точным N вместо старого приближённого подсчёта. Доступность раскрытия — N ≥ 2 для конкретного инстанса сетки (не брейкпоинт экрана). В Широком режиме N всегда 1 → раскрытие само отключается тем же правилом, без отдельной проверки на режим.

**Разрешение графика (по минутам / 5-минутные бакеты) — без сравнения ширины.** Для каждой карточки при построении данных всегда считаются оба варианта: по минутам и схлопнутый в 5-минутные бакеты (без всякого сравнения с px). Какой из них показать — решает не построение данных, а состояние конкретного рендера этой карточки в конкретный момент:
- обычная карточка в Компактном режиме (в ряду с любым N, включая случайное N=1 на узком экране) → всегда 5-минутки;
- карточка, раскрытая по клику (Компактный режим) → всегда по минутам;
- любая карточка в Широком режиме → всегда по минутам.

Важно: Компактный режим, где N случайно получился 1 (например, на телефоне контейнер узкий) — это не то же самое, что Широкий режим и не то же самое, что раскрытая карточка. Такая карточка всё равно 5-минутка: разрешение графика определяется тем, какой режим выбран и раскрыта ли карточка, а не тем, сколько сейчас пикселей у неё по факту.

## Что убирается

- `CardSizeMode` в старом смысле (Small/Large с раздельными шириной/высотой каждый) — остаётся только один режим-переключатель (Компактный/Широкий), не про размер, а про алгоритм раскладки.
- `expandedWidthPxInput`/`expandedHeightPxInput` у сетки карточек — ширина раскрытой карточки больше не настройка, вычисляется как вся свободная ширина контейнера; высота единая для всех карточек.
- `MINUTE_COLLAPSE_CARD_WIDTH_THRESHOLD_PX` (600px) и оба завязанных на ширину computed (`useCollapsedMinutes$$`, `useCollapsedMinutesForExpanded$$`) — сравнение с шириной исчезает полностью, заменяется на два явных флага "раскрыта ли карточка" / "весь ли грид в Широком режиме".
- Привязка возможности раскрытия и видимости переключателя к `isDesktopScreen$$` внутри сетки карточек (сам `DeviceInfoService` используется в других местах приложения — не трогается).

## Что остаётся как есть

- Способ измерения контейнера (`ResizeObserver` на хосте сетки, измерение зазора через `getComputedStyle`) — используется и Компактным, и Широким режимом.
- Способ вставки раскрытой карточки сразу после её ряда — та же логика, тот же N (только теперь точный, не приближённый).
- Оба варианта данных (по минутам / 5-минутки) уже строятся сегодня в отдельных случаях (`display`/`expandedDisplay`) — теперь строятся всегда безусловно, без условия "только если пороги разошлись". Выбор между ними переносится в грид (по флагам "раскрыта" / "весь грид широкий"), а не в построение данных.
- Механизм явного сохранения настроек (кнопка "Сохранить" → PUT) — новая плоская форма размера + режим сохраняются тем же путём.

## Согласованные решения

- Переключатель в шапке остаётся, но переключает не размер (Small/Large), а алгоритм раскладки (Компактный auto-fit / Широкий один-в-строке-на-всю-ширину).
- Высота — одна настройка на все карточки во всех состояниях, без исключений.
- Разрешение графика (минуты/5-минутки) определяется ролью карточки в моменте (обычная / раскрытая / Широкий режим), а не сравнением с пиксельной шириной. Старая константа 600px убирается полностью, ничем не заменяется.

## Правки после ручной проверки

Проблема: при плавном протаскивании края окна карточки заметно мерцали при уменьшении (ряд на кадр перенахлёстывался, крайняя колонка временами пустая), при увеличении — незаметно. Причина: ширина каждой карточки применялась как явный px, вычисленный в JS и выставленный через Angular-биндинг ПОСЛЕ того, как `ResizeObserver` узнавал новый размер контейнера — на уменьшении этот кадр задержки означал, что карточки временно шире, чем реально помещается, и `flex-wrap` успевал неправильно перенести ряд до прихода исправленного значения.

Исправлено: сетка карточек переведена с `flex flex-wrap` + явный px-width на CSS Grid (`grid-template-columns: repeat(N, minmax(0, 1fr))`), где N — то же самое число колонок, посчитанное тем же алгоритмом. Непрерывное изменение ширины колонок при ресайзе теперь считает сам браузер синхронно, в один layout-проход — JS больше не участвует в потоке "измерил → выставил px", участвует только в редком дискретном решении "сейчас должно быть N колонок". Раскрытая по клику карточка растягивается на все колонки через `grid-column: 1 / -1`, а не через явную px-ширину. `widthPxInput` убран из `MetricChartCard` целиком — карточка теперь просто заполняет свою grid-ячейку (её единственный потребитель — `metric-card-grid`).
