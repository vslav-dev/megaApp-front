# Выделение выбранных продуктов на графике калорий — фронтенд (основной план)

Парный план бэкенда: [46-product-history-chart-highlight.implementation-plan.md](../../megaapp-back/plans/46-product-history-chart-highlight.implementation-plan.md).

## Описание

Продукты, выбранные в блоке «История продукта» (план [31](31-food-product-history.implementation-plan.md)), подсвечиваются на графике «Калории за день»: столбик каждого дня делится на выбранные продукты (основание, акцентный цвет) и всё остальное (выше, приглушённым тоном). Несколько выбранных продуктов суммируются в один сегмент. Точность в пределах 1% не важна.

## Как было

- График калорий — Chart.js, столбики stacked: «Ккал за день», «Виртуальные ккал» (серия всегда 0, читалась только графиком), линия нормы. Тултипов и легенды нет.
- Данные графика — `FoodStatsService`: ряд по дням → срез по слайдеру → при длинном периоде дни склеиваются в недели (>363 дней) и месяцы (>4 лет): среднее за день, период берётся только если заполнены все его дни.
- Агрегация — 12 параллельных массивов и три копии списка рядов (создание, срез дня, срез периода) прямо в сервисе; добавление ряда = правка 8 мест.
- Состояние истории — сервис на `FoodScreen`, без связи со статистикой. Бэк отдавал только граммы и % от нормы.

## Решение

### Визуал

- Столбики в абсолютных ккал: основание — выбранное, выше — остальное; сумма = ккал дня. Высота стека и линия нормы сохраняют смысл при 80%, 100%, 120%: нормировать на 100% не нужно (отвергнуто — теряет перебор/недобор и ломает линию нормы).
- Общее основание у выбранного сегмента — его высоту легко сравнивать по дням.
- Цвет выбранного — оттенок вне синей гаммы и вне статусных (красно-оранжевый, зелёный), из палитры графиков, учитывает тему. «Остальное» при активном выборе — приглушённый тон (прежний «виртуальный» цвет, переименован в `muted`); без выбора график выглядит как раньше.
- Под графиком — легенда «Выбранные продукты / Остальное», только при выборе (раньше легенды не было, без неё цвет непонятен).
- Только график калорий: у линии веса нет столбика, который можно разделить.

### Недели и месяцы

Среднее линейно: среднее выбранного + среднее остального = среднее целого. Поэтому выбранное — обычный ряд в общей агрегации, с тем же правилом полноты периода; отдельной логики нет.

### Данные

- Бэк отдаёт `kcal` события (было скрыто как промежуточная величина). Иначе пришлось бы восстанавливать ккал из округлённого %: ошибка до ~0,5% нормы на запись копится при нескольких приёмах за день.
- Состояние истории переезжает в root: `FoodStatsService` (root) должен читать «ккал выбранных по дням», а сервис экрана ему недоступен. Побочно выбор переживает уход с экрана еды; сбрасывается при выходе из аккаунта, как статистика.
- Подписка на изменения дневника (локальные и пришедшие с других устройств): столбик обновляется сразу из дневника, выбранная часть должна догнать. Обновление фоновое — без оверлея, при ошибке остаются прежние данные. Фоновый запрос отменяет предыдущий; индикатор загрузки сбрасывается завершением любого последнего запроса (иначе подписка, снятая фоновым запросом, оставила бы оверлей навсегда).
- Удалённый из выбора продукт перестаёт учитываться сразу, не дожидаясь ответа.

### Рефакторинг агрегации

Склейка дней в недели/месяцы и срезы вынесены из `FoodStatsService` в чистый модуль со списком рядов (`STATS_CHART_SERIES` в общих типах — единственный источник). Новый ряд = одна строка в списке + код, который его заполняет и рисует; копий агрегации больше нет. Мёртвая серия «виртуальные ккал» удалена, её слот в стеке занял выбранный ряд. Поведение остальных рядов не меняется (проверено прежними спеками и новыми на чистый модуль).

### Не делаем

- Цвет на каждый продукт (до 20 продуктов — палитра нечитаема; расширять можно позже через ряд на продукт).
- Тултипы на графике калорий (не было, отдельная задача).
- Отдавать выбранное из `/stats?…`: статистика кэшируется на бэке и хранится local-first на фронте, привязывать её к набору продуктов нельзя.
- Считать выбранное из локального дневника: он покрывает окно, а не всю историю.

### Баги
1. Выбранная часть столбика в последние три дня отстаёт от самого столбика и не появляется офлайн
   - **Класс:** B
   - **Важность:** мелочь, но стоит поправить
   - **Как сейчас работает:** общая высота столбика за последние три дня берётся из локального дневника и растёт сразу. Выбранная часть берётся из истории продукта с сервера, и запрос уходит только после того, как сервер подтвердил запись.
   - **Что не так:** добавили в дневник отслеживаемый продукт — столбик вырос в приглушённом цвете, и только через время ответа сервера в основании появился акцент (цвет «перескакивает»). Без сети запись сохраняется локально, подтверждения нет, и акцент не появляется, пока не вернётся связь. Сейчас это скрыто зажимом «остальное не ниже нуля», то есть величина считается из двух разных источников.
   - **Как поправить:** для трёх живых дней считать выбранное из локального дневника (по записям, чей продукт отслеживается), как считается и общая высота; для остальных дней — из истории с сервера.

   - **Объём правки:** средний — расчёт выбранного для живых дней в статистике, тест на него.
   - **Рекомендация:** не чинить — класс B, «мелочь» и правка средняя; расхождение временное и в рамках допуска 1% из постановки.

2. Карта «ккал выбранных по дням» пересоздаётся без изменения содержимого и каждый раз пересчитывает всю модель статистики
   - **Класс:** B
   - **Важность:** мелочь, но стоит поправить
   - **Как сейчас работает:** карта собирается заново при любом изменении каталога (картинка продукта, правка любого продукта) и при каждом ответе истории; сигнал сравнивается по ссылке, поэтому новая карта считается изменением.
   - **Что не так:** даже при пустом выборе правка любого продукта в каталоге заставляет пересобрать весь ряд дней, недели и месяцы, ленты серий и перерисовать график. После каждой правки дневника при выбранном продукте это происходит второй раз — когда приходит фоновый ответ истории с теми же числами.
   - **Как поправить:** задать сигналу сравнение по содержимому (размер и значения), тогда неизменная карта ничего не запускает.
   - **Как будет работать после правки:** модель статистики и график пересчитываются только при реальном изменении выбранного.

   - **Рекомендация:** чинить — класс B, правка малая.

3. Правило разделения столбика на выбранное и остальное и цвет «остального» живут в приватном методе графика и повторяются в легенде

   - **Как будет работать после правки:** одно правило в одном месте, логика проверяется тестом.

Поля `muted` и `mutedAlpha` цветов графика удалены, график больше не зависит от наличия выбора. Это заменяет пункт «Остальное — приглушённый тон» раздела «Визуал».
