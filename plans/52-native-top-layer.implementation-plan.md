# 52 — Нативный top layer вместо ручных z-index

Только фронт (`megaapp-front`, подмодуль `src/ui-kit`). Парный план в бэке не нужен.

## Проблема

- Вложенная модалка (подтверждение «Перегенерировать картинку?» поверх формы редактирования продукта) не затемняла нижнюю модалку.
- Кнопки подтверждения не влезали в окно.

## Корень

- `ZLayerService` вручную раздаёт z-index; затемнение — отдельный элемент в `body` с z-index «слой − 10».
- Первая модалка и затемнение второй оказывались «вперемешку»: затемнение второй лежало под карточкой первой.
- Контент формы проецируется в `v-modal` через `ng-content` → DI-цепочка `PARENT_LAYER_ID` не доходит до вложенной модалки; иерархия слоёв строится случайно.
- Escape слушается на `document` в каждой открытой модалке → закрываются все стопкой сразу.
- Выпадающий список колеса считал сдвиг `position: fixed` через обход предков в поисках `transform` — костыль под ручные слои.
- Тосты держатся числом `z-[9999]` — тоже «число против числа».
- `default-modal`: две кнопки `width: 100%` в одну строку при фиксированных 300px.

## Целевая архитектура

Порядок слоёв отдаётся браузеру (top layer):

- Модалка = нативный `<dialog>` + `showModal()`. Затемнение = `::backdrop`. Стек вложенных окон, inert фона, фокус и возврат фокуса — на браузере.
- Выпадающий список, тултип, колесо, контейнер тостов = `popover` в top layer; z-index не нужен. Фиксированное позиционирование top layer не зависит от `transform` предков → костыль в колесе удаляется.
- Одна маленькая директива включает/выключает popover; больше слоёв в приложении не регистрируется.
- Удаляются: `ZLayerService`, `VBackdropDirective`, `PARENT_LAYER_ID`, все `z-index` слоёв.

## Решения и крайние случаи

- Escape: событие `cancel` диалога перехватывается и превращается в `closeOutput`; закрывается только верхнее окно. Открытое колесо перехватывает Escape первым.
- Клик мимо: закрывает только если нажатие И отпускание были на подложке (выделение текста с выходом за карточку не закрывает).
- Прозрачная подложка (`isBackdropDimmed = false`, например при удержании слайдера цвета): `::backdrop` становится прозрачным, окно остаётся; смена на лету без переоткрытия.
- Прокрутка страницы под модалкой блокируется (`overflow: hidden` у `html`, пока есть открытый модальный `dialog`).
- Тосты должны быть выше модалок: контейнер — popover, поднимается наверх при каждом новом тосте и при открытии модалки (последний открытый слой всегда сверху). Пока открыта модалка, тосты видны, но неинтерактивны (фон inert) — осознанное ограничение платформы.
- Нативное закрытие (`close`) без ведома родителя синхронизируется выходом `closeOutput`.
- `default-modal`: шире, кнопки в переносимой строке — не вылезают за рамку при длинных подписях.
- jsdom не знает `showModal`/`showPopover` → заглушки в тестовой инициализации.

## Что не делаем

- Не трогаем таймер 150 мс на blur в выпадающем списке (не связан со слоями).
- Не меняем визуальный вид компонентов, кроме затемнения и ширины `default-modal`.

## Упрощение после аудита (07.11.2026)

Разбор каждого узла: можно ли проще.

- Директива top layer: вход «держаться над модалками» (input + слушатель события на каждом экземпляре) нужен только тостам → вынесен из директивы в компонент тостов. Директива теперь: показать при появлении + `bringToFront`.
- `v-modal`, список, тултип, колесо, блокировка прокрутки, заглушки jsdom: проще нельзя без потери поведения.
- Колесо остаётся на `manual`: `auto` закрывается на pointerdown раньше клика по триггеру и открывался бы заново.
- `openOutput` модалки никем не используется в приложении; оставлен как публичный API ui-kit (решение за владельцем).

- ✅ Директива без input и слушателя; тосты сами поднимаются на событие открытия модалки
- ✅ lint, `tsc` (app + spec), build, `npm test`
