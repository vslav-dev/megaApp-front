# Именованный тип статистики вместо позиционного тюпла

Парный документ: `megaapp-back/plans/19-food-stats-named-type.implementation-plan.md` — точные имена JSON-полей нужно свести с этим документом до реализации, иначе фронт молча получит `undefined` вместо ошибки.

Breaking change по решению пользователя (2026-08-02): бэк и фронт раскатываются одновременно, обратная совместимость со старым форматом ответа не поддерживается.

## Что делаем и зачем

`Stats` — `{[date]: [number, number, number, number, boolean?]}`, доступ по индексу (`dateStats[2]` — потреблённые ккал, ниоткуда не видно). Меняем на объект с именованными полями, зеркально бэкенду.

## Текущая реализация (обзор)

- `types.ts` — `Stats` объявлен как `{[id: string]: [number, number, number, number, boolean?]}`.
- `food-stats.service.ts`:
  - `prepareChartData()` — деструктурирует каждую запись по позиции: `const [weight, weightAvg, kcal, kcalTarget, isVirtualKcalDay] = values;`.
  - `updateStats()` (оптимистичное обновление веса/ккал дня, вызывается из `FoodDiaryService`/`setUserBodyWeight`/дневниковых правок) — строит новый кортеж вручную по тем же позициям.
  - Больше нигде `Stats` напрямую не читается — единственный файл-потребитель, кроме объявления типа.

## Направление

- `Stats` → объект с именованными полями (например `weight`, `weightAvg`, `consumedKcal`, `targetKcal`, `isVirtualKcalDay`) вместо кортежа — точные имена ключей зафиксировать вместе с бэкенд-документом перед реализацией.
- `prepareChartData()` — деструктуризация по позиции заменяется на чтение именованных полей.
- `updateStats()` — построение объекта по позиции заменяется на spread с точечной правкой нужных полей.
- **Кэш в `localStorage`.** Механизм инвалидации по версии уже существует и не требует ничего нового строить:
  - `shared/const.ts`: `CACHE_SCHEMA_VERSION` — единое число на все пользовательские кэши сразу (не по одному ключу — одна версия на всё приложение).
  - `shared/cache.ts`: `buildCacheKey()` подмешивает эту версию в каждый ключ (`{key}:{userId}:v{CACHE_SCHEMA_VERSION}`); `purgeStaleCacheVersions()` при каждом старте приложения удаляет из `localStorage` все записи с известным базовым ключом, но с **другой** версией в суффиксе.
  - `main.ts` — `purgeStaleCacheVersions()` вызывается один раз, безусловно, до старта Angular-приложения.
  - Значит старый (тюплованный) `food_stats` из `localStorage` **не** повиснет мёртвым грузом — код просто перестанет попадать на старый ключ (версия в суффиксе другая), а сам стартовый вызов удалит его физически. Ничего строить не нужно — только поднять `CACHE_SCHEMA_VERSION` (сейчас `2`) на единицу как часть этой же правки.
  - **Побочный эффект, о котором стоит знать заранее**: версия одна на всё приложение, не по ключу — поднятие версии ради `food_stats` заодно очистит и все остальные кэши (`food_diary`, `food_catalogue`, `money_snapshot`, `metrics_detail`, настройки и т.д.). У всех пользователей при первом заходе после деплоя — один полный перезапрос всех данных с сервера вместо чтения кэша, дальше всё работает как обычно. Разово и безопасно, но не только по `food_stats` — если это нежелательно, можно вместо этого добавить `food_stats` персонально в список ключей с собственным суффиксом версии, но это усложнение сверх того, что уже есть, и уже отдельное решение.

## Область охвата

- `types.ts` (`Stats`), `food-stats.service.ts` (`prepareChartData`, `updateStats`), `const.ts` (`CACHE_SCHEMA_VERSION`).
- Не входит: `StatsChartData` и всё, что строится из него (`prepareAggregatedData`, слайдер диапазона дат и т.д.) — эти структуры уже именованные, не тюплы, не трогаем.

## Затронутые флоу

| Флоу | Сейчас | После |
|---|---|---|
| Загрузка графика статистики (`getStats()`) | Парсит массивы по позиции | Парсит именованные поля — молча сломается, если имена ключей разойдутся с бэком (см. чеклист) |
| Оптимистичное обновление дня (правка веса/ккал без ожидания сервера) | Строит кортеж по позиции | Строит объект по именованным полям, тот же набор данных |
| Первый заход в приложение после деплоя этой правки | Кэш `food_stats` в старом формате из `localStorage` | `purgeStaleCacheVersions()` удаляет его при старте (как и все остальные пользовательские кэши, см. выше) — секция стата тянется с сервера заново, один раз |
