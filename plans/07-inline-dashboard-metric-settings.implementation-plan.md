# Inline Dashboard Metric Settings — Implementation Plan

## Статус

- ✅ Текущая цепочка отображения, выбора, сортировки и сохранения изучена.
- ✅ Реализация выполнена, ждёт ручной проверки в браузере.

## Задача

- Удалить гигантский список выбора метрик из общего Settings.
- Перенести выбор метрики для Dashboard и её порядок в саму карточку.
- Включать режим редактирования отдельной кнопкой в верхней панели `/metrics`.
- Сохранить мгновенное обновление Dashboard и текущую серверную синхронизацию.

## Текущее устройство

- Сервисная вкладка строит карточки из каталога метрик и реально обнаруженных метрик.
- Dashboard использует те же карточки, но фильтрует их через сохранённый выбор пользователя.
- Выбор хранится как `service → metric → order`; Dashboard сортирует карточки по order, затем по техническому имени.
- Включение первой метрики автоматически включает её сервис на Dashboard и назначает следующий order.
- Общий Settings повторно строит полный список тех же метрик. Это и создаёт огромную дублирующую таблицу.
- Изменение настройки сразу обновляет signals и localStorage. Полный снимок через 5 секунд сохраняется на сервер.
- Во время запроса элементы настройки блокируются. Ошибка возвращает последний подтверждённый снимок.
- Бэк хранит настройки как непрозрачный JSON. Формат данных, API, миграции и backend-код менять не требуется.

## Целевой UX

- В верхней панели появляется отдельная кнопка редактирования карточек с активным состоянием.
- Режим действует на карточки и Dashboard, и открытой сервисной вкладки.
- Обычный режим сохраняет текущую верхнюю строку: название, tooltip, последнее или наведённое значение.
- Режим редактирования заменяет только эту строку на компактный ряд:
  - checkbox показа на Dashboard;
  - название метрики;
  - числовой order только для включённой метрики.
- График, размеры карточки, данные, crosshair и переключение гранулярности не меняются.
- Включение метрики сразу добавляет её на Dashboard в конец сервиса.
- Изменение order сразу переставляет карточки.
- Снятие checkbox на Dashboard сразу удаляет карточку из Dashboard. В сервисной вкладке она остаётся и доступна для повторного включения.
- Выход из режима сразу возвращает обычные заголовки. Режим не сохраняется между загрузками страницы.
- Во время серверного сохранения checkbox и order блокируются тем же общим флагом, что текущие настройки.

## Граница общего Settings

- Полный grid метрик и его повторное построение удаляются.
- Остаётся компактный блок уровня сервисов:
  - показ сервиса на Dashboard;
  - порядок сервисов на Dashboard;
  - показ сервиса в верхней панели.
- Эти настройки нельзя корректно перенести в отдельную карточку метрики: они относятся ко всему сервису.
- Размеры карточек, синхролиния, refresh/cache и severity остаются без изменений.

## Архитектура

### Страница метрик

- Владеет временным режимом редактирования и всей бизнес-логикой выбора.
- Переиспользует текущие операции включения, выключения и изменения order.
- Передаёт каждой карточке текущее состояние выбора, order и блокировку сохранения.
- Обрабатывает события карточки с известными service и metric.
- Удаляет вычисление отдельного списка опций для гигантского Settings: карточки уже являются полным визуальным каталогом.

### Карточка метрики

- Остаётся presentation-компонентом.
- Получает режим, enabled, order и disabled через signal inputs.
- Отдаёт только события изменения checkbox и order через signal outputs.
- Условно меняет внутреннюю строку заголовка, не заменяя весь компонент и canvas.
- Не знает о структуре сохранённых настроек и не обращается к сервисам.

### Сервис настроек

- Не меняется.
- Существующий формат выбора, локальное сохранение, debounce, блокировка, rollback и серверный endpoint полностью переиспользуются.

## Важные сценарии

- Каталогизированная и обнаруженная вне каталога метрика получают одинаковые inline-настройки.
- Выбранная ранее, но исчезнувшая из каталога и данных метрика остаётся управляемой на Dashboard, пока там существует её карточка.
- Одинаковые order сохраняют текущий стабильный fallback по техническому имени.
- Отключение последней метрики оставляет пустой сервис без визуальной строки Dashboard; текущая service-настройка не повреждается.
- Ошибка сохранения возвращает подтверждённый набор: удалённая карточка снова появляется, добавленная исчезает.
- Переключение режима не должно уничтожать Chart.js instance или сбрасывать hover/crosshair.
- Скрытая верхняя вкладка сервиса остаётся настраиваемой через компактный сервисный блок Settings.
